# 선택적 공용 매칭 서버 배포

v3.6 EXE는 첫 실행자가 매칭 호스트가 되므로 별도 서버 배포가 필수는 아닙니다. LAN 자동 검색·인터넷 직접 접속은 [사용 설명서](../사용설명서.md#6-온라인-준비-첫-pc가-호스트)를 참고하세요. 이 문서는 첫 PC를 계속 켜 두지 않고 모두 같은 고정 주소를 사용하려는 경우의 선택적 배포 방법입니다.

전투 프로토콜이 8로 바뀌었으므로 공용 서버도 최신 코드로 재배포하고 두 클라이언트를 모두 v3.6으로 교체하세요. 이전 v3/v3.1/v3.2/v3.3/v3.4/v3.5 서버와는 연결되지 않습니다.

현재 공개 서버는 운영하지 않습니다. 배포 후 발급된 HTTPS URL을 양쪽 EXE 로비의 **매칭 호스트 주소**에 입력하면 됩니다. GitHub는 파일 다운로드 장소이며 정적 Pages만으로 매칭 API를 운영할 수 없습니다.

## 가장 간단한 배포: Render Blueprint

[Render에서 이 저장소 배포하기](https://render.com/deploy?repo=https://github.com/imsosorrybutiloveyou/teken)

1. Render 계정으로 로그인하고 이 저장소를 연결합니다. 비밀번호·토큰은 게임이나 채팅에 입력하지 않습니다.
2. 저장소의 `render.yaml`을 사용하는 Blueprint로 서비스 생성을 진행합니다.
3. 런타임은 Docker, 상태 검사 경로는 `/api/health`입니다. 서비스는 게임 페이지와 매칭 API를 함께 제공합니다.
4. 빌드·상태 검사가 성공하면 Render에서 발급한 **실제 HTTPS 서비스 URL**을 복사합니다.
5. 두 플레이어가 EXE의 **온라인 대전 → 매칭 호스트 주소**에 같은 주소를 넣고 연결합니다. 또는 두 사람이 해당 HTTPS 주소로 웹 게임을 열어도 됩니다.
6. PLAYER MATCH에서 한 명이 방을 생성하고 상대가 목록에서 입장합니다. 퀵 매치는 제거했습니다.

설정은 무료 플랜을 지정하지만, 서비스의 무료 정책·이용 가능 여부와 결제 요청은 제공 업체의 현재 안내를 확인하세요. 무료 인스턴스는 유휴 상태 후 잠들 수 있어 최초 연결 때 지연이 생길 수 있습니다.

## Docker로 직접 운영

```sh
docker build -t axis-advance:v3 .
docker run --rm --name axis-advance -p 8787:8787 axis-advance:v3
```

기본 포트는 8787입니다. 외부 서비스는 HTTPS 역방향 프록시로 연결하고, SSE(`text/event-stream`) 응답의 버퍼링을 끄세요. 서버는 10초마다 SSE heartbeat를 보냅니다. HTTPS 서비스를 443번으로 제공하고 컨테이너 8787번은 프록시 뒤에 두면 됩니다.

상태 검사:

```sh
curl -f http://127.0.0.1:8787/api/health
```

정상 응답에는 `service: "axis-matchmaking"`, `version: 6`이 포함됩니다. 게임은 같은 주소의 `/`에서 열립니다.

## Node.js로 직접 운영

Node.js 22.12 이상(검증: 24)이 필요합니다.

```sh
npm ci
npm run build
npm start
```

`PORT` 환경 변수로 포트를 변경할 수 있습니다. 서버 런타임은 Node.js 표준 라이브러리만 사용합니다. `server/`, `src/characters.js`, `dist/`, `package.json`이 운영에 필요합니다.

## 웹 게임 / EXE 연결 설정

- 웹 게임이 매칭 서버에서 함께 제공될 때는 현재 사이트 URL을 자동으로 사용합니다.
- EXE는 시작 시 LAN 호스트를 자동 검색하거나 자신이 호스트가 됩니다. 공용 서버는 로비 주소 칸에 직접 입력하거나 `--host https://배포-주소`로 참가합니다.
- 웹 게임의 기본 서버는 `VITE_MATCH_SERVER_URL`로 지정할 수 있습니다. EXE는 로컬 연결 창구를 우선합니다. 공개 URL만 설정하고 인증 키를 넣지 마세요.
- 로컬 검증은 `npm run build && npm start`로 두 브라우저가 같은 로컬 서버에 접속하면 됩니다. 이 로컬 주소를 다른 인터넷 사용자에게 보내는 방식은 아닙니다.

## 운영 범위

- 대기열·방·캐릭터 선택·WebRTC 신호 교환만 서버가 담당합니다. 실제 전투 입력과 스냅샷은 두 플레이어 사이 P2P로 흐릅니다.
- 세션은 무작위 토큰으로 구분하며, 서버는 요청·본문 크기·접속 세션 수를 제한합니다. 플레이어 이름은 계정 인증된 이름이 아닙니다.
- 한 인스턴스의 메모리에 대기열과 방을 저장합니다. 서버 재시작 시 목록과 매칭 상태는 초기화됩니다. 여러 인스턴스로 확장할 때는 공유 저장소와 공용 이벤트 전달을 추가해야 합니다.
- 연결이 일시적으로 끊기면 15초 동안 서버 세션 복구를 기다립니다. 복구하지 못하면 상대에게 종료를 알리고 방·매칭을 정리합니다.
- 현재 Google STUN만 사용합니다. 서버를 배포해도 모든 NAT에서 P2P가 되는 것은 아닙니다. 대칭 NAT·차단망까지 지원하려면 TURN 중계를 별도로 구성해야 합니다. 현재 EXE/웹 클라이언트에 TURN은 설정되어 있지 않습니다.
- 롤백 넷코드는 없고 호스트가 60Hz 판정을 진행하며 참가자는 왕복 지연의 영향을 받습니다.
