# AXIS — 3D Fighting Arena

Three.js와 브라우저 WebRTC로 만든 오리지널 3D 격투 게임입니다. 외부 캐릭터나 게임 에셋 없이 생성한 캐릭터와 경기장을 사용합니다.

처음 실행하는 분은 **[실행 및 사용 설명서](사용설명서.md)**를 보세요. PC 실행, 키 조작, 친구 초대, 배포, 문제 해결을 순서대로 설명합니다.

## Windows에서 바로 실행

[**Windows EXE 다운로드 — AXIS-Windows-x64.exe**](https://github.com/imsosorrybutiloveyou/teken/raw/refs/heads/main/downloads/AXIS-Windows-x64.exe)를 다운로드해 더블클릭하세요. Windows 10/11 64비트용이며, Node.js나 별도 설치 과정 없이 기본 브라우저에서 게임이 열립니다. 게임하는 동안 함께 열린 실행 창을 유지하고, 종료할 때 해당 창도 닫으세요. 실제 Windows 실행 검증은 아직 하지 않았습니다. 자세한 절차는 [사용 설명서](사용설명서.md)를 참고하세요.

배포용 실행 파일과 [SHA-256 체크섬](downloads/AXIS-Windows-x64.exe.sha256)은 저장소의 `downloads/` 폴더에 포함되어 있습니다. 개발자가 새로 빌드한 결과는 `release/`에 생성됩니다. 새 버전을 배포하려면 EXE와 체크섬을 함께 `downloads/`에 복사한 뒤 커밋하세요. 체크섬 확인 방법은 [다운로드 안내](downloads/README.md)에 있습니다.

개발자가 EXE를 다시 만들려면 Node.js 의존성 외에 Go 1.26 이상을 설치하고 실행합니다.

```sh
npm ci
npm run package:windows
```

Go 경로가 기본 `go`가 아니라면 `GO_BINARY` 환경 변수로 실행 파일 경로를 지정할 수 있습니다. 빌드 명령은 게임을 새로 빌드하고, 내장 파일 HTTP 테스트를 실행하고, Windows x64 PE 형식을 확인한 뒤 EXE와 SHA-256 파일을 생성합니다. Windows 외의 OS에서도 교차 빌드할 수 있습니다. 런처는 Go 표준 라이브러리만 사용하며 게임 파일을 실행 파일에 내장하고 `127.0.0.1`의 임의 포트에만 서버를 엽니다.

## 실행

Node.js 22.12 이상(현재 검증: 24), WebGL과 WebRTC를 지원하는 최신 데스크톱 브라우저가 필요합니다.

```sh
npm ci
npm run dev
```

기본 포트는 5173입니다. 프로덕션 빌드는 `npm run build`, 빌드 결과 확인은 `npm run preview`로 실행합니다. 배포 시 `dist/`를 HTTPS 정적 호스팅에 올리면 됩니다. 개발용 localhost에서도 WebRTC를 사용할 수 있습니다.

## 게임

- CPU 연습 대전 / 2인 WebRTC P2P 온라인 대전
- 실제 3D 좌표에 기반한 이동, 횡이동, 공격 방향·사거리·공격 폭 판정
- 상단·중단·하단·잡기, 서서 가드와 앉아서 가드
- 공격 입력 버퍼, 연계기, 띄우기와 공중 콤보, 타격 경직
- 60초 라운드, 2라운드 선승, 체력·승점·콤보 HUD
- 두 가지 카메라 시점, 선택 가능한 효과음, 연습전 일시정지

현재 KAI와 REN은 외형이 다르고 같은 기술 세트를 사용합니다. 키보드 조작을 전제로 하며 화면 배치는 모바일에도 대응합니다.

| 키        | 조작                                         |
| --------- | -------------------------------------------- |
| A / D     | 월드 좌우 이동: 상대 위치에 따라 접근 / 후퇴 |
| W / S     | 깊이 방향 횡이동                             |
| J         | 상단 잽. 다시 입력하면 중단 스트레이트       |
| K         | 중단 돌려차기. 잽 이후에는 스피닝 피니시     |
| U         | 하단 스윕                                    |
| I         | 중단 라이징 어퍼: 띄우기                     |
| O         | 근접 잡기: 가드 무시, 앉아서 회피            |
| L         | 서서 가드: 상단·중단 방어                    |
| Shift     | 앉기: 상단 회피                              |
| Shift + L | 앉아서 가드: 하단 방어, 중단에 취약          |
| Esc       | 연습전 일시정지 / 계속하기                   |

가까운 거리에서 `J → J → K`, `I → J → K`를 시도하세요. 키는 계속 누르기보다 차례로 누릅니다. 현재 공격 중 다음 공격 하나를 예약할 수 있으므로 기술의 타이밍에 맞춰 입력하세요. 첫 공격을 헛치거나 상대가 횡이동·가드하면 콤보가 이어지지 않을 수 있습니다.

## 온라인 대전

두 사람이 같은 앱을 각각 브라우저에서 엽니다. 계정이나 별도 게임 서버는 필요하지 않습니다.

1. 방장: **온라인 대전 → 방 만들기 → 초대 코드 생성**을 누르고 전체 코드를 상대에게 전송합니다.
2. 참가자: **온라인 대전 → 초대받아 참가**에서 초대 코드를 붙여넣고 **응답 코드 생성**을 누릅니다.
3. 참가자가 생성된 응답 코드를 방장에게 전송합니다.
4. 방장이 응답 코드를 붙여넣고 **응답 적용 · 연결**을 누르면 대전이 시작됩니다.

방장은 P1 KAI, 참가자는 P2 REN을 조작합니다. 게임 판정은 호스트가 60Hz로 계산하고, 참가자의 입력을 받아 20Hz 스냅샷으로 동기화합니다. 온라인 일시정지는 비활성화되며, 다음 대전 시작은 호스트만 할 수 있습니다. 연결 해제 후에는 새 코드로 다시 연결합니다.

공개 Google STUN(`stun.l.google.com:19302`)으로 연결 경로를 찾습니다. 게임 데이터는 WebRTC DataChannel을 통해 암호화되어 전달됩니다. TURN 중계 서버가 없으므로 일부 대칭 NAT·회사 방화벽에서는 연결이 불가능할 수 있습니다. 이 경우 다른 네트워크를 사용해야 합니다. 별도 시그널링 서버 대신 코드 교환을 사용하므로 두 코드의 교환이 모두 필요합니다.

현재 버전은 호스트 기준 판정을 사용하는 프로토타입이며 롤백 넷코드를 포함하지 않습니다. 참가자는 왕복 지연의 영향을 받습니다. 서로 다른 인터넷망에서의 연결 가능성은 각 네트워크 환경에 따라 달라집니다.

## 검증

```sh
npm test                 # Node 내장 테스트: 전투·가드·콤보·횡이동·라운드·입력 검증·코드 형식
npm run build            # 프로덕션 빌드
npx playwright install chromium
npm run dev              # 별도 터미널에서 서버 실행
npm run test:browser     # 실제 브라우저 두 개로 P2P 왕복 검증
```

브라우저 검사는 WebGL 초기화, 이동, 일시정지, 기술표, 실제 offer/answer 교환, 원격 횡이동과 타격 피해 동기화, 연결 해제, 모바일 가로 넘침을 검증합니다. `CHROMIUM_PATH`로 기존 Chromium 실행 파일을 지정하고 `TEST_BASE_URL`로 테스트 주소를 바꿀 수 있습니다. 화면 캡처는 `/tmp/axis-desktop.png`, `/tmp/axis-mobile.png`에 저장됩니다.

코드: `src/combat.js` 전투 판정, `src/scene.js` 3D 렌더링·애니메이션, `src/network.js` P2P 연결, `src/main.js` 입력·UI·게임 루프. 로컬 번들 글꼴은 SIL Open Font License이며 라이선스는 `public/fonts/`에 포함되어 있습니다.
